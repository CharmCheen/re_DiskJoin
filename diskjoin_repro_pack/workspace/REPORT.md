## Core algorithm understanding

- **Bucketization** (`lib/Kmeans.h`, `lib/ClusterIO.h`): sample centers, build HNSW over centers, 2-choice assignment, write each bucket contiguously, record centroids/radii/assignment.
- **Bucket graph** (`lib/DiskJoin.h`): HNSW KNN per bucket, angle-based probabilistic truncation using `error_bound`, keep upper-triangle candidate tasks.
- **Gorder** (`lib/Gorder.h`): greedy graph reordering via incremental sibling-key updates; returns rank permutation.
- **Belady cache** (`lib/Cache.h`): precomputed future-use lists; max-heap evicts bucket with farthest next access. `LRUCache` exists but is not on the main path.
- **Execution** (`lib/DiskJoin.h`): load candidate buckets, self-join + cross-bucket L2² checks under `epsilon² = radius`, sample recall over IDs divisible by 100000.

Important caveats: the code batches all candidates of a target bucket, rather than strictly processing two buckets per edge; the paper's triangle-inequality Eq.(1) filter is not used in graph construction — this is by design, since §5.2 replaces it with HNSW KNN + probabilistic (Algorithm 3) pruning. The offline demo is pedagogical, not exact Gorder.

## Main risks / open items

- **MISMATCH G3-01**: bucket assignment uses `add2choice` 2-choice load balancing (`Kmeans.h:127-146`) whereas the paper (§5.1) says "nearest center". *Gate 4A correction: the Gate 3 claim "all 120 toy centroids not in their own bucket" was an audit-script bug (bucket index vs data-vector ID confusion); real behavior is 120/120 centroids in own bucket; ~15–16% of sampled vectors go to the 2nd-nearest center. Mismatch itself stands.*
- **MISMATCH G3-02**: printed recall is `%100000`-sampled count / `gt`, not the paper's full `|R∩R'|/|R|`; double-counts pairs whose both endpoints are sampled (n≥100000). *(Gate 4A evaluations all use the full-oracle protocol.)*
- **Bug G3-03 (confirmed by ASan)**: `aligned_alloc` buffer freed with `delete[]` (`ClusterIO.h:183` vs `:207`) → UB. *Fixed in the gate4a isolated copy (`free`), regression-verified; reference repo unchanged.*
- O_DIRECT `read`/`lseek` return values unchecked (`ClusterIO.h:198-199`) → silent short reads possible (G3-04).
- `read_fbin` does not check `ifstream` open failure (`ClusterIO.h`) → garbage n/d on a bad path (observed as 600 s timeouts + SIGFPE during gate4b1 holdout setup); robustness observation recorded, not fixed in the frozen reference.
- **Leak (Gate 4B-0, LeakSanitizer)**: `ClusterWriter::writeClusters` never frees its `new char[...]` write buffer (P3-small: 430,080 B) and a `new float[batch_size*d]` (256 B) → process exit 1 under LeakSanitizer; no other memory errors; `detect_leaks=0` gives rc=0 with identical output. Reference repo unchanged. *Fixed in the gate4b1 isolated copy (commit `f1ac471`); pre-fix LSan evidence retained.*
- **Bug (Gate 4B-1, ASan)**: `updateable_heap::sift_down` reads `right_son(crawler)` (= `storage[current_bound]`) at guard nodes before the bounds check, at two sites (`utils/heap.h`) → heap-buffer-overflow read on a full heap; unreachable under reference Belady semantics (update only sifts up; pop sifts at even current_bound) — exposed by the new lru_forced policy. *Fixed guard-first in the gate4b1 isolated commit `51a90f7` (defined-case semantics unchanged; defaults byte-identical to frozen dumps); reference repo unchanged.*
- **Bug (Gate 5A, ASan)**: hnswlib `searchBaseLayer` SSE prefetch operand `*(datal+j+1)` reads one `tableint` past the linklist when `j+1==size` (`lib/hnswlib/hnswalg.h:264`, with `USE_SSE` unconditionally defined in `hnswlib.h:4`); level≥1 linklists are separate `malloc(84×level+1)` blocks → 3-byte OOB read on a full (20-link) list. First triggered by the real BigANN100K 1000-center HNSW graph (synthetic 120/240-center graphs never trigger it); the loaded value feeds only `_mm_prefetch` → zero functional impact (guard-patched run byte-identical to unpatched). *Diagnostic guard archived as `workspace/gate5a/patches/gate5a_prefetch_guard.diff`; instrumented source restored byte-identical (sha256 verified); reference repo unchanged.*
- **Distortion (Gate 5A, print-only)**: `DiskJoin.h:245` declares `float dist_comp` — a float32 counter; above 2²⁴ each increment rounds (ULP=16), making the printed value accumulation-order-dependent (+66/+114 on BigANN100K; true order-invariant value 154,113,486 recomputed offline from the task graph). Synthetic counts never exceeded 2²⁴, so 4B-1's invariance check was exact. No effect on results or decisions; reference repo unchanged.
- Self-join assumes `target_tasks[0] == target_cluster` without assertion — verified true on 3k/12k, but no runtime guard (G3-05/§3A).
- `exit(0)` inside `search` can silently terminate without recall output (G3-05; effectively unreachable on tested data).
- Strict `<` on squared distance vs paper `≤ ε` — boundary-only difference (G3-06).
- Gorder window `w=2C/K≈452 > n=120` on the toy → window-removal branch never runs (G3-11). *Gate 4A: activated at small mem_budget (window=4, 116 slides, task multiset provably invariant) — closed for ablation purposes.*
- Bucket radii / Eq.(1)-style `prune` exist but are dead code (`rangeSearchBaseLayer` never called); live path is HNSW top-K + Algorithm 3 (G3-08).
- Legacy CMake (`2.8`, `OPENMP_FOUND`, `-lboost`) works on cmake 3.22.1 with a deprecation warning; cmake 4.x untested.
- ACM formal PDF missing → paper-level comparison and arXiv↔formal parity remain unverified.
- **OMP>1 nondeterminism** (G3-14 root-caused in Gate 4A): parallel HNSW center-graph build shifts pair sets on overlapping data; OMP=1 is the determinism control for all controlled comparisons.
